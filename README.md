# jjinmap

공공데이터로 장소를 보는 지도. 광고가 섞이지 않은 신호만 쓴다.

> 상태: **설계 중, 코드 없음.** 스택·화면·렌더러 미정. 아래 "미해결"이 확정되기 전에는 코드를 쓰지 않는다.

## 문제

맛집 지도는 이미 많다. 전부 같은 약점을 공유한다 — **평점과 리뷰는 살 수 있다.**
협찬 블로그, 대가성 리뷰, 부풀린 별점이 걸러지지 않은 채 "맛집"으로 올라온다.

## 접근

공공데이터에는 광고가 섞일 수 없다. 대신 평점·리뷰 같은 인기 지표도 없다.
그래서 인기를 직접 묻는 대신 **협찬으로 조작할 수 없는 신호**로 대신한다.
(*"돈으로 살 수 없는"이 아니다 — 핫플 모드의 신호는 실제 결제금액이다.
요점은 돈이 안 든다가 아니라, 광고비를 써서 그 숫자를 만들 수 없다는 것이다.*)

## 두 모드

서로 다른 API를 물고, 하나의 점수로 섞지 않는다.

| | **찐 모드** | **핫플 모드** |
|---|---|---|
| 질문 | 오래 살아남았는가 | 지금 뜨는가 |
| 신호 | **영업 지속기간** = 인허가일자 → 오늘 | 실시간 결제 건수·금액구간 |
| 폐업 데이터 용도 | 지도에서 제외하는 필터 (표시 대상 아님) | — |
| 출처 | LOCALDATA 지방행정인허가 | 서울 열린데이터광장 `citydata` |
| 해상도 | 개별 가게 (핀) | 서울 주요 장소 120곳 (폴리곤/히트맵) |
| 갱신 | 일 단위 | 원본 10분, **실제 가능 3시간** (아래 쿼터 참고) |

해상도가 다르므로 signal provider 인터페이스는 `granularity`(`store` \| `area`)를 갖는다.
두 모드를 한 화면에 어떻게 얹을지(토글/탭/레이어)는 미정.

## 확인된 사실

`실호출` = 실제 API 응답으로 확인. `문서` = 공식 문서·1차 자료로만 확인. (2026-08-27)

### LOCALDATA 지방행정인허가

- `문서` 인허가일자·폐업일자·영업상태 제공 → 지속기간 지표 성립
- `문서` **좌표계 함정**: 좌표를 `EPSG:2097`로 표기하지만 실제는 `EPSG:5174`.
  두 좌표계는 원점 경도의 `0.0028902777778` 보정값 유무만 다르다.
  라벨대로 2097로 변환하면 전 지점이 일정하게 어긋난다. **5174로 읽고 WGS84(4326)로 변환.**
  단 어긋나는 **크기(m)를 아직 측정하지 않았다** — 회귀 테스트를 쓰려면 이 수치가 필요하다.
- `실호출` **서울 한정 경로 확보.** `localdata.go.kr`은 여전히 안 닿지만, 서울 열린데이터광장이
  같은 데이터를 자기 호스트로 미러링한다: `openapi.seoul.go.kr:8088` → `LOCALDATA_072404`(일반음식점).
  **536,710건 전량 수신 완료.** 39필드에 `APVPERMYMD`(인허가일자)·`DCBYMD`(폐업일자)·
  `TRDSTATENM`(영업상태)·`UPTAENM`(업태)·`X`/`Y`(TM 좌표)·`BPLCNM`·주소가 **한 레코드에 다 있다.**
  1콜 1,000행이라 전량 537콜(개발계정 일일 쿼터의 54%). **전국은 여전히 미해결**(미해결 9번).
- `실호출` **서울 일반음식점 실측(2026-08-27, 전수).** 영업중 **120,326** / 폐업 416,379 —
  **폐업률 77.6%**. 영업기간 중앙값 **8.1년**, p95 33.2년, 최대 115.2년.
- `실호출` **인허가일자는 실제 영업 시작을 과소평가한다.** 같은 번지·같은 상호에 더 이른
  인허가 기록이 있는 영업중 업소가 **3,388곳(2.8%)**, 숨은 연차 중앙값 4.9년·최대 46.6년,
  20년 이상 과소평가 341곳. **이 2.8%는 바닥값이다** — 상호 변경이나 이전은 이 방법으로 안 잡힌다.
  실제 비율은 더 높고, 얼마나 높은지는 모른다 (미해결 1번).

### 소상공인시장진흥공단 상가(상권)정보

- `실호출` 경도·위도를 `lon`/`lat`(WGS84)로 **직접** 제공 → 좌표 변환 불필요
- `실호출` 강남역 반경 500m에 6,617건. 기준년월 `stdrYm=202606`
- `실호출` 컬럼 39개에 **시간 관련 필드가 전무** (개업·폐업·등록일 없음)

### 서울 열린데이터광장 `citydata`

- `실호출` **장소 120곳.** `POI001`~`POI130` 중 결번 10개
  (POI022, 028, 057, 062, 065, 069, 075, 097, 099, 113). 상한(130) ≠ 개수(120).
  전체 목록 [`data/seoul_areas.json`](data/seoul_areas.json)
- `실호출` **이 120곳은 상권이 아니다.** 역·교통 46, 공원·한강 28, 관광특구 7, 고궁 4, 기타 35.
  한강공원과 경복궁이 포함된다. "상권 120곳"으로 부르면 핫플 모드의 전제가 틀어진다.
- `실호출` `LIVE_CMRCL_STTS`에 신한카드 결제 데이터가 그대로 들어온다:
  `AREA_SH_PAYMENT_CNT`(건수), `AREA_SH_PAYMENT_AMT_MIN/MAX`, 업종별 `CMRCL_RSB[]`,
  `AREA_CMRCL_LVL`(상권 활성도, 관측값 `바쁜`). **금액은 스칼라가 아니라 구간이다** —
  랭킹하려면 규칙이 필요하다. 인구 혼잡도(`AREA_CONGEST_LVL`)는 여기가 아니라 아래 인구 블록에 있다.
- `실호출` `RSB_MCT_TIME`은 월 단위(예: 202607) — **가맹점 수는 실시간이 아니다**
- `실호출` **결제 업종 대분류는 음식·음료 / 유통 / 의료 셋뿐이다.** 강남역 기준 `CMRCL_RSB[]`
  중분류 7개(한식, 제과/커피/패스트푸드, 기타요식, 할인점/슈퍼마켓, 편의점, 병원, 약국)의
  건수 합이 `AREA_SH_PAYMENT_CNT`와 **정확히 일치**한다 → 상위 N개를 자른 게 아니라 이게 전부다.
  두 가지가 따라온다. (1) **숙박·문화·관광 업종이 없다** — 결제 신호로는 관광지 소비를 볼 수 없다.
  (2) 병원 34건이 제과/커피 36건과 맞먹는다 — 결제를 그대로 쓰면 **맛집 신호에 병원·약국·편의점이
  섞여 들어온다.** 걸러내는 규칙이 필요하다.
  단 이는 장소 1곳·시각 1개 관측이며, 장소·시간대별로 대분류가 달라지는지는 미확인.
- `실호출` `LIVE_PPLTN_STTS`에 인구 신호가 통째로 들어온다: `AREA_CONGEST_LVL`(4단계),
  `AREA_PPLTN_MIN/MAX`, 성별 비율, **연령 8구간**(`PPLTN_RATE_0`~`_70`),
  `RESNT_PPLTN_RATE`/`NON_RESNT_PPLTN_RATE`(상주/비상주), 그리고 `FCST_PPLTN` —
  **시간 단위 인구 예보**. 국적·외국인 필드는 응답 전체에 **없다.**
- `실호출` 응답 최상위 블록은 **17개**. 핫플 모드가 쓰는 건 `LIVE_CMRCL_STTS` 하나뿐이고,
  나머지 16개는 **같은 호출에 딸려온다** — 추가 쿼터 없이 이미 손에 있다(미해결 12번).
- `문서` 한 번에 1개 장소씩만 호출 가능. 인구 5분 / 상권 10분 갱신

### 호출 쿼터 — 10분 갱신은 개발계정으로 불가능

개발계정 1,000건/일, 운영계정 100,000건/일. 그런데 장소당 1콜이므로:

```
120곳 × 6회/시 × 24시간 = 17,280건/일   →  개발계정 한도의 17.3배
개발계정으로 가능한 전 장소 갱신 = 하루 8회 (약 3시간 간격)
```

**운영계정 승인 없이는 "실시간 핫플"이 성립하지 않는다.** 승인 전까지는 3시간 간격이거나,
장소를 추려야 한다.

## 설계를 바꾸는 제약: 두 소스에 공통 키가 없다

| | 소상공인 상가정보 | LOCALDATA 인허가 |
|---|---|---|
| 주는 것 | 좌표(WGS84 직접), 정제된 업종분류 | 인허가일자, 폐업일자, 영업상태 |
| 없는 것 | **시간축 전부** | 위경도 (TM만, 라벨도 틀림) |
| 식별자 | 상가업소번호 | 인허가관리번호 |

두 식별자는 서로 무관하다. 둘을 합치려면 상호명+주소 매칭이 필요하고,
그 정확도가 찐 모드 품질의 상한이 된다.

**단, 그 전에 답할 질문이 있다 (미해결 0번): 애초에 합쳐야 하는가?**
LOCALDATA도 주소와 업종을 갖고 있고, 좌표는 5174로 읽으면 나온다.
"소상공인 쪽 좌표·업종이 더 정확하다"는 건 아직 **측정한 적 없는 가정**이다.
이 가정이 무너지면 매칭 문제 자체가 사라진다.

## 미해결 (확정 전 코드 금지)

0. [ ] **소상공인 상가정보가 정말 필요한가** — LOCALDATA 단독으로 좌표·업종이 충분한지 실측.
   충분하면 위의 "핵심 난제"가 통째로 사라진다. **다른 무엇보다 먼저 답할 것.**
1. [ ] **인허가일자가 실제 영업 시작을 얼마나 과소평가하는가** — 질문이 바뀌었다.
   "리셋되는가"는 데이터로 부분 답이 나왔다: **같은 자리·같은 이름 기준 2.8%가 과소평가되고,
   그 중앙값이 4.9년이다.** 남은 것은 **상호 변경·이전까지 포함한 진짜 비율**이다.
   2.8%는 그 케이스를 못 잡는 바닥값이므로, 위쪽 한계를 모른다.
   1차 문서(영업자 지위승계 조항)로 규칙 자체를 확인하는 일은 여전히 남아 있다.
2. [ ] **지속기간을 업종·지역별로 정규화하는가** — 30년 세탁소와 30년 노포가 같은 점수를 받는다.
   대상 업종 범위(음식점만? 전체?)도 미정.
3. [ ] **"찐" 임계값** — 몇 년부터인가. 절대값인가 백분위인가.
4. [ ] **매칭 평가 설계** — 0번이 "필요하다"로 나올 때만. 정답셋·표본크기·지표(precision/recall)·
   라벨러가 전부 없다. 현재 게이트는 "게이트를 만들겠다"는 약속일 뿐이다.
5. [ ] **전국 TM 원점** — 찐 모드는 전국 가능인데 5174(중부원점)는 한 존이다.
   LOCALDATA가 전국에서 단일 좌표계인지 미확인. 아니면 중부 밖 핀이 조용히 어긋난다.
6. [ ] **결제금액 구간 랭킹 규칙** — MIN/MAX 구간으로 순위를 매기는 방법.
7. [ ] **데이터 시점 불일치** — 상가 `202606`, 가맹점수 `202607`, 결제 실시간.
   두 달 묵은 업소 명부 위의 "실시간"을 어떻게 표기할 것인가.
8. [ ] **평점·리뷰 부재** — 확인된 필드엔 없으나 "없다"고 명시한 1차 문서 미확보. 단정 보류.
9. [ ] **`localdata.go.kr` 도달 불가 — 서울은 우회 확보, 전국은 미해결.**
   서울분은 `openapi.seoul.go.kr`의 `LOCALDATA_072404`로 전량 받았다(위 '확인된 사실' 참고).
   **남은 것은 서울 밖이다** — 찐 모드를 전국으로 하려면 다른 경로가 필요하다.
   원래 실측(4개 호스트):
   `www.localdata.go.kr`은 443 침묵 타임아웃(20s) / 80 즉시 거부, `openapi.localdata.go.kr`은
   **DNS A 레코드 자체가 없다** — 차단이 아니라 존재하지 않는 호스트명이다. 반면
   `openapi.seoul.go.kr:8088`은 200, `apis.data.go.kr`은 400 응답.
   → **차단은 공공데이터 전반이 아니라 이 한 도메인 한정이고, 막힌 건 찐 모드뿐이다.**
   남은 것: (a) 국내에서도 같은지 미확인 — 같다면 API 명세 문제, 다르면 배포·CI 리전 제약.
   (b) 인허가 데이터에 닿는 다른 경로. 도달 가능한 `apis.data.go.kr`이 지방행정인허가를
   서빙하는지가 첫 갈래다.
10. [ ] **이용약관** — 신한카드 파생 결제데이터·LOCALDATA의 재배포/상업적 이용 범위 미확인.
11. [ ] **저장·수집 구조** — 전국 인허가는 수백만 행. 저장소·수집 잡·스케줄러 미정.
12. [ ] **미사용 데이터 — 응답의 17분의 1만 쓴다.** `citydata` 최상위 17블록 중 쓰는 건
    `LIVE_CMRCL_STTS` 하나다. 안 쓰는 것: 인구 전체(혼잡도, 인구수, 성별, 연령 8구간,
    상주/비상주, **시간 단위 예보**), 결제 쪽 성별·연령·개인/법인 비중, 그리고 도로·주차·
    지하철·버스·따릉이·날씨·충전소·행사. 전부 추가 쿼터 없이 이미 온다.
13. [ ] **지역 범위** — 핫플은 서울 한정, 찐은 전국 가능. 부산 사용자는 반쪽만 본다.
14. [ ] **웹/앱, 지도 렌더러**
15. [ ] **미쉐린·블루리본 배지를 지도에 표시** (2026-08-27 발의, 다음 세션 검토)
    핀 위에 미쉐린/블루리본 로고를 얹는 안. 비자명한 점 둘:
    (a) **찐 모드와 경쟁한다.** 이 목록들 자체가 광고로 살 수 없는 신호라 jjinmap의 전제를
    이미 만족한다. 성격만 다르다 — 배지는 커버리지 낮고 정확도 높은 신호, 지속기간은
    커버리지 높고 정확도 미지의 신호다. 단순 부가기능이 아니라 부분적 대안이며,
    G0 결과에 따라 주·부가 뒤집힐 수 있다.
    (b) **미해결 10번(약관)을 새로 건드린다.** 로고는 상표이고 목록에도 권리가 있을 수 있다.
    미쉐린은 자기 sitemap까지 CloudFront WAF로 막는다 — 재배포에 관대한 쪽이 아니라는 신호다.

> 처음으로 시작됐다. 아래 "사람이 할 일 2건"이 막고 있는 지점이다.

   붙여넣으면 된다. 이게 G0 **판정 A**의 유일한 남은 입력이다.
2. **G0 판정 B — 상위 5% 30곳 육안 검사.** 표는 `analysis/g0_judgment_B_sample.md`에 있다.
   "이 집 때문에 이동할 만한가"가 명백히 아닌 곳이 16곳 이상이면 불합격 (사전등록 기준).
   판정 전에 **"찐맛집"의 한 문장 정의**를 먼저 적어둘 것 — 이 프로젝트는 아직 타깃을
   정의한 적이 없고, 그게 대리 지표를 검증 못 해온 이유다.

### 이 세션이 바꾼 것

- **G1(데이터 경로) 사실상 해결** — 서울 한정. 536,710건 전량 로컬에 있다.
- **G0(신호 타당성) 게이트 신설** — `/hate` 결과. 기존 G1~G4는 지속기간을 *계산할 수 있는가*만
  물었고 *무엇을 뜻하는가*는 묻지 않았다. G0이 나머지 전부에 선행한다.
- **G5 자기모순 수선** — `.re0/`가 gitignore라 "합격선 커밋이 결과보다 앞선다"를 증명할 수
  없었다. 합격선 블록의 해시를 [`PREREG.md`](PREREG.md)에 남기는 방식으로 대체했다.
- **미해결 1번의 질문이 바뀜** — "리셋되는가" → "얼마나 과소평가하는가"(바닥값 2.8%).
- **미해결 0번이 '불필요' 쪽으로 크게 기움** — LOCALDATA 한 레코드에 좌표·업종·시간축이 다 있다.

### ⚠️ 다른 머신으로 옮길 때

`.re0/`(게이트·설계), `data/raw/`(537콜 덤프), `analysis/g0_ranked.jsonl`은 **전부 gitignore다.**
clone하면 없다. 커밋되어 살아남는 건 `PREREG.md`·`analysis/g0_tenure.py`·README뿐이고,
덤프는 537콜을 다시 써야 한다(개발계정 일일 쿼터의 54%).

### 스택·화면

여전히 없다. 그건 위 미해결에 있다 — "열면 바로 빌드"가 아니라 "열면 바로 계획"이다.

**키**: `.env`(gitignore됨). 필요한 항목은 [`.env.example`](.env.example) 참고 —
`SBIZ_API_KEY_ENCODED`/`SBIZ_API_KEY_DECODED`(공공데이터포털), `SEOUL_API_KEY`(서울 열린데이터광장).
두 포털은 서로 다른 키를 쓴다. 공공데이터포털 키는 인코딩/디코딩 두 형태가 있고,
쿼리스트링을 재인코딩하는 클라이언트에는 디코딩키를 써야 한다.

맥락이 비면 `catchup`. 이 사이클은 이미 열려 있으므로 `/re0-plan`을 다시 치지 않는다 —
`.re0/iteration/v0.1.0-source-decision/`가 현재 케이스북이다.

순서:

1. 위 "사람이 해야 함" 2건을 처리해 **G0을 판정**한다.
2. G0 불합격이면 → 찐 모드의 신호를 다시 정의하는 것이 다음 사이클의 게이트다.
   G0 합격이면 → G4(좌표 어긋남 미터 측정) → G3(미해결 0번) 순으로 진행.
3. 사이클을 닫을 때 **`/re0-memo`**, 그 다음 **`/hate`**(사람이 직접), 그리고 `re0-work` 재시작
   여부 판정. 은퇴는 **`/re0-release`**(사람이 직접) — 버전은 그때 확정한다.

**사람이 직접 쳐야 하는 스킬** (에이전트가 대신 못 부른다):
`/hate`, `/macrothink`, `/feynman`, `/prism`, `/re0-plan`, `/re0-git`, `/re0-release`.
`re0-memo`·`nba`·`catchup`·`mandela`는 에이전트가 부를 수 있다.
