# jjinmap

공공데이터로 장소를 보는 지도. 광고가 섞이지 않은 신호만 쓴다.

> 상태: **v0 제작 중.** 2026-08-27 저장소 소유자가 산출물을 **v0로 승격**했다 — 버리는
> 스케치가 아니다. "코드 없음" 규칙은 여기서 끝났다. 지도 렌더러는 **MapLibre GL JS +
> 정적 HTML**로 확정(미해결 8번의 일부). 프레임워크·백엔드는 없고, 그건 미결정이 아니라
> **v0가 축 하나짜리 정적 데이터라 필요가 없다는 결정**이다.
>
> **2026-08-27 — 재범위했다.** 영업 지속기간이 품질의 대리 지표로 성립하는지를 측정했고
> (게이트 G0) **불합격**이다 — 미쉐린 서울 빕구르망 28곳의 백분위 중앙값 **47.1**, 무작위(50)
> 보다 낮다. 그 뒤 배지(미쉐린·블루리본) 레이어도 **제외**했다(상표·재배포 노출, 유료 게재 논란).
>
> 남은 설계는 **기존 API가 실제로 재는 것을 그 이름으로 표시하는 지도**다 — 나이와 결제.
> 대리 지표를 쓰지 않으므로 정답셋·사전등록·벤치마크가 **필요 없다.**
>
> **같은 날 — 킬 게이트(이용약관) 통과.** 두 소스 다 공공누리 1유형이라 출처표시만 하면
> 상업적 이용·변경이 된다. 살아남은 유일한 전제("광고비로 만들 수 없는 숫자")를 막는 것은 없다.
>
> **이름은 `jjinmap`으로 확정.** 단 "찐"의 뜻을 못 박았다 — 아래 [「찐의 정의」](#찐의-정의).
>
> **2026-08-28 — 나이 축을 외부 정답으로 처음 쟀고, 축이 자기 이름대로 안 잰다는 것이
> 나왔다.** 인허가일자가 재는 것은 「영업 지속기간」이 아니라 **「대장 등록 후 경과」**이고
> (G-A: 노포 구간 과소평가 하한 중앙값 **10.8년**), 그 오차가 화면에서 하는 일도 쟀다
> (G-H: 인증 노포는 상위 6%에 들지만 **상위 100곳에는 1곳뿐**). 화면 문구는 그에 맞춰
> 고쳤다 — 「최소 N년」은 폐기하고 「대장 기준 N년」을 쓴다.

## 문제

맛집 지도는 이미 많다. 전부 같은 약점을 공유한다 — **평점과 리뷰는 살 수 있다.**
협찬 블로그, 대가성 리뷰, 부풀린 별점이 걸러지지 않은 채 "맛집"으로 올라온다.

## 접근

공공데이터에는 광고가 섞일 수 없다. 대신 평점·리뷰 같은 인기 지표도 없다.

한 번은 그 공백을 **대리 지표**로 메우려 했다 — 오래 살아남았으면 좋은 집일 것이다.
측정해보니 아니었다(아래 [G0](#g0--영업-지속기간은-품질-신호가-아니다-2026-08-27-측정-완료)).
그래서 방향을 바꿨다:

> **대리 지표를 쓰지 않는다. 데이터가 실제로 재는 것을, 그 이름으로 표시한다.**

지속기간은 품질이 아니라 **나이**를 잰다. 그러면 "1968년부터 영업 중"은 대리 지표가 아니라
**사실**이고, 사실은 정답셋으로 채점할 대상이 아니다. 순위를 매기지 않으므로 임계값도,
정규화도, 벤치마크도 필요 없다 — 축을 보여주고 사용자가 직접 고른다.

같은 규칙이 핫플 모드에도 적용된다. `AREA_SH_PAYMENT_*`의 `SH`는 신한이다.
그러므로 그 숫자는 "결제 건수"가 아니라 **"신한카드 결제 건수"** 이고, 그렇게 표시한다.

*"광고가 섞이지 않는다"는 전제는 그대로 살아 있다 — 인허가 대장도 카드 결제도
광고비를 써서 그 숫자를 만들 수 없다. 내려놓은 것은 **그 숫자가 품질을 뜻한다**는 주장이다.*

## 찐의 정의

> **찐 = 오래 살아남은 것.** 인허가 대장 기준의 사실이며, **맛있다는 뜻이 아니다.**

이름은 `jjinmap`으로 간다. 결정일 2026-08-27, 결정자는 저장소 소유자.

RETRO가 지난 사이클의 뿌리 원인으로 지목한 것이 **"'찐맛집'을 정의한 적이 없다"** 였다.
이 절이 그 청구서다. 여기서부터 "찐"은 가설이 아니라 **정의**이고, 정의는 게이트에 걸리지 않는다.

**G0과 충돌하지 않는 이유.** G0이 반증한 문장은 *"오래 살아남음 ⇒ 미쉐린이 고를 만큼 맛있음"*
(백분위 중앙값 47.1 < 무작위 50)이다. 위 정의는 그 함의를 주장하지 않는다 — 왼쪽 절반만
남기고 화살표를 지웠다. 제품명에 "맛집"이라는 단어가 들어가지 않는 것이 여기서 작동한다.

따라오는 두 가지를 같이 못 박는다:

- **찐은 배지가 아니라 축이다.** "오래"의 임계값을 정하지 않는다. 등급 라벨("이 집은 찐입니다")을
  붙이는 순간 닫힌 항목 3번(임계값 없음)이 되살아나고, 그건 순위 매기기의 다른 이름이다.
  축을 보여주고 **사용자가 직접 자른다.**
- **찐 = 나이 축이다. 핫플 모드는 찐이 아니다.** 제품 전체가 두 레이어 중 하나의 이름을 쓰는
  구조다. 의도된 것이고, 결제 레이어를 "찐"이라 부르지 않는다.

**바깥에서는 그렇게 안 읽힐 수 있다.** "찐맛집"은 이미 굳은 말이라 사용자는 품질로 받아들인다.
이건 논리 오류가 아니라 **전달 위험**이고, 화면 문구(미해결 5번)에서 흡수한다 —
"오래된 순"이라고 쓰지 "좋은 순"이라고 쓰지 않는다.

## 두 모드

서로 다른 API를 물고, 하나의 점수로 섞지 않는다.

| | **나이 축** = 찐 축 | **핫플 모드** |
|---|---|---|
| 표시하는 것 | 이 가게가 몇 년째인가 | 이 장소가 지금 얼마나 붐비는가 |
| 신호 | **영업 지속기간** = 인허가일자 → 오늘 | **신한카드** 결제 건수·금액구간 |
| **주장의 강도** | 사실 (대장 기준). **품질 주장 없음** | 사실 (한 카드사 기준). 시장 전체 아님 |
| 폐업 데이터 용도 | 지도에서 제외하는 필터 (표시 대상 아님) | — |
| 출처 | LOCALDATA 지방행정인허가 (서울 미러) | 서울 열린데이터광장 `citydata` |
| 해상도 | 개별 가게 (핀), 영업중 120,326곳 | 서울 주요 장소 120곳 (폴리곤/히트맵) |
| 갱신 | 일 단위 | 원본 10분, **실제 가능 3시간** (아래 쿼터 참고) |
| 범위 | **서울** (v0) | **서울** |

해상도가 다르므로 signal provider 인터페이스는 `granularity`(`store` \| `area`)를 갖는다.
**두 모드를 하나의 점수로 섞을 이유는 이제 없다** — 둘 다 서로 다른 사실이므로 별개 레이어로 둔다.
토글/탭/레이어 중 무엇으로 할지는 미정(미해결 8번).

배지(미쉐린·블루리본) 레이어는 **제외했다** — 아래 "닫힌 항목" 참고.

## 화면 문구 규칙

**사용자가 보는 문자열의 정본이다.** 화면은 데이터가 실제로 재는 것을 그 이름으로만 쓴다.

| 자리 | 문자열 | 근거 |
|---|---|---|
| 축 이름 | **인허가 후 경과** | 파생값이 아니라 `APVPERMYMD` → 오늘. 식이 이름에 들어 있다 |
| 축 설명 | **오래된 순. 좋은 순이 아니다.** / **개업연도가 아니라 대장 등록일이다.** | 「찐의 정의」— 전달 위험을 문구가 흡수한다 |
| 핀 팝업 | **{상호} · 대장 인허가일 {YYYY-MM-DD} · 대장 기준 {N}년** | 주장을 빼고 기록만 쓴다 |
| 한계 — 방향 | 상호 변경·이전·경매 인수는 새 신고가 되어 날짜가 다시 시작된다 (식품위생법 제39조) | 오차 방향의 1차문서 근거 |
| 한계 — 크기 | 백년가게 **35곳 대조에서 13곳(37%)이 대장 나이 30년 미만**, 모자란 햇수 중앙값 **10.8년**·최대 22.0년. **이 값은 하한이다.** 단 오래된 집만 모은 목록이라 **노포 쪽 이야기이고 지도 전체의 평균이 아니다** | G-A. 「대개 길다」는 하한이 아니므로 수치로 바꿨다 |
| 한계 — 커버리지 | 영업중 120,331곳 중 **109,066곳(90.6%)만 지도에 있다.** 나머지는 대장에 좌표가 없고 결측률은 구마다 다르다(종로구 28.3%가 최대) | 실측. 이게 없으면 화면이 조용히 거짓말한다 |
| 한계 — 입력 오류 | 1960년 이전 2건은 성립하지 않는다(1911 청담동·1936 영등포동). 해당 핀에 경고 줄이 붙는다. **레코드는 지우지 않는다** | 오차가 양방향으로도 틀린다는 실물 증거 |
| 출처 | 서울열린데이터광장 LOCALDATA 일반음식점 인허가(OA-16094) · **공공누리 제1유형** + 하이퍼링크 | 공공누리 1유형의 유일한 의무 |

**금지 목록** — 등급 라벨(찐/추천/베스트), 순위 표시, 임계값 경계선, "좋은"·"맛있는"·"맛집"
계열 단어, 색·크기가 등급을 뜻하는 범례. **색은 연속 축이고 50년에서 포화한다**(포화 사실은
범례에 적혀 있다).

⚠️ **아직 화면에 없는 것 — G-H가 만든 숙제.** 「가장 어두운 = 가장 오래된」으로 읽히는데
**나이 순 상위 100곳은 노포 명단이 아니다**(1위는 입력 오류, 상위 20곳은 대장이 시작된
1963~1967년 등록에 몰린다). 게다가 램프가 50년에서 포화해 **최상단 265곳이 서로 구분되지
않으므로**, 사용자는 축의 맨 위에서 순서를 읽을 수 없다. 이 한계는 아직 문구에 없다.
각주로 될 일인지 축을 고칠 일인지가 다음 사이클의 첫 질문이다.

## 확인된 사실

`실호출` = 실제 API 응답으로 확인. `1차문서` = 제공기관의 공식 페이지·약관·데이터셋 안내.
`2차자료` = 보도자료·기사·개인 블로그. `추정` = 근거 없음. (2026-08-27)

### 이용조건 — 킬 게이트 통과 (2026-08-27)

두 소스 다 **공공누리 제1유형**이다. 출처만 표시하면 **상업적 이용과 변경이 허용**된다.

| 소스 | 이용허락범위 | 저작권자 | 근거 |
|---|---|---|---|
| LOCALDATA 서울 미러 (일반음식점) | 공공누리 1유형 : 출처표시 (상업적 이용 및 변경 가능) | 서울특별시 | `1차문서` [OA-16094](https://data.seoul.go.kr/dataList/OA-16094/S/1/datasetView.do) |
| 실시간 상권현황 (신한카드 결제) | 공공누리 1유형 : 출처표시 (상업적 이용 및 변경 가능) | 서울특별시 · **제3자 저작권 표시 없음** | `1차문서` [OA-22385](https://data.seoul.go.kr/dataList/OA-22385/F/1/datasetView.do) |

플랫폼 약관도 같은 방향이다 — 제11조 *"서울시는 열린데이터광장 서비스에 대하여 저작자 및 출처
표시 조건으로 자유이용을 허락함을 원칙으로 합니다"* (`1차문서`
[이용약관](https://data.seoul.go.kr/etc/accessTerms.do)).

**우리가 지는 의무는 출처표시 하나다.** 온라인 서비스이므로 출처 웹사이트로의 **하이퍼링크**까지
포함된다 (`1차문서` [공공누리 이용조건](https://www.kogl.or.kr/info/license.do)).

**남는 잔여 노출 두 가지 — 지금은 발동하지 않지만 기록해둔다.**

- 공공누리 1유형에는 *"제3자의 저작권 대상이거나 제3자가 소유한 정보"* 는 이용자 책임이라는
  단서가 있고, 서울시 약관 12②는 *"제3자의 권리가 포함된 사실을 **인지하고 이용한 경우는
  제외**"* 라고 면책 범위를 좁힌다. 상권현황 데이터셋이 제3자 저작권을 **없음**으로 표시하므로
  현재는 문제되지 않으나, 우리는 이제 `SH`=신한임을 **아는 상태**다.
- OA-16094 페이지에 **서비스 종료·이관 안내**가 떠 있다(서울 데이터 허브로 이관 중). 오늘
  537콜은 정상이었지만 엔드포인트 수명은 우리 통제 밖이다 → 미해결 1번.

**따라서 나이 축도 핫플 모드도 죽지 않는다.** 재범위 뒤 살아남은 유일한 전제
("이 숫자들은 광고비로 만들 수 없다")를 표시·재배포 측면에서 막는 것은 없다.

**⚠️ 단 게시 경로가 조건부 제약 둘을 새로 붙인다 — 데이터가 아니라 인프라 쪽이다.**
둘 다 **형태가 같다: 지금은 안 걸리고, 상업화하면 걸린다.**

| | 지금 (비상업 지도) | 상업화하면 |
|---|---|---|
| **OSM 공용 타일** | 요구사항 만족, 위반 아님 | *"access may be withdrawn at any point"* — 정책이 직접 대안을 권한다. `1차문서` |
| **GitHub Pages** | 걸리지 않는다 — 상거래·SaaS 사이트가 아니다 | *"not ... allowed to be used as a free web-hosting service to run your online business, e-commerce site, or any other website ... primarily directed at either facilitating commercial transactions or providing commercial software as a service"* `1차문서` |

**공공누리 1유형이 상업적 이용을 허용해도 이 두 경로는 그걸 지탱하지 않는다.**
각각의 탈출구는 있다 — 타일은 Protomaps PMTiles 자체 호스팅(13번), 호스트는 유료 전환이나 이전.
정적이라 이전 비용이 거의 0이라는 것이 여기서 값을 한다.

### LOCALDATA 지방행정인허가

- `문서` 인허가일자·폐업일자·영업상태 제공 → 지속기간 지표 성립
- `1차문서` **좌표계 함정**: 좌표를 `EPSG:2097`로 표기하지만 실제는 `EPSG:5174`.
  데이터셋 페이지가 직접 못 박는다 — *"좌표안내 : 중부원점TM(EPSG:5174) 좌표계에 따른 해당위치의

  라벨대로 2097로 변환하면 전 지점이 일정하게 어긋난다. **5174로 읽고 WGS84(4326)로 변환.**
- `실호출` **어긋남의 크기 = 255 m (2026-08-27, 측정 완료).** 한국관광공사 TourAPI의 WGS84
  좌표를 정답으로 삼아 도로명주소+상호 완전일치 **155쌍·23개 구**를 대조했다 — 2097 가정은
  거리 중앙값 **256.6 m**, 5174 가정은 **6.2 m**. 두 가설 사이의 거리가 서울 전역에서
  255.0~255.7 m로 **폭 0.7 m**라 계통 오차(데이텀 이동)임이 확인된다.
  **데이터셋 페이지의 `EPSG:2097` 라벨은 틀렸다.** 잔차 6.2 m는 TourAPI 지점과 건물 좌표의
  차이를 포함하므로 **우리 변환 오차의 상한**이지 실제값이 아니다.
  산출물 검산(`points.json` 109,066건 ↔ TourAPI 재호출 371곳·26구)도 중앙값 **6.8 m**로
  일치한다. 재현: `python3 analysis/gx_datum.py`, `python3 analysis/d2_pipeline_check.py`

### G-A — 나이 축은 「영업 지속기간」이 아니다 (2026-08-27, 측정 완료)

**대장 인허가일자가 실제 창업연도와 얼마나 어긋나는지 외부 정답으로 처음 쟀다.**

**정답 소스**: 중소벤처기업부 **백년가게** 지정리스트(odcloud

**지정 요건이 「업력 30년 이상」**이므로 제3자 인증된 하한을 준다. 수집 절차가 인허가 대장과
독립이다(면접·자료 조사). 합격선은 측정 전에 고정했다([`PREREG.md`](PREREG.md) 해시).

| | 값 |
|---|---|
| 서울 소재 백년가게 ∩ LOCALDATA 영업중 (도로명주소+상호 완전일치) | **35곳** |
| **모순 (대장 나이 < 30년)** | **13곳 / 35 = 37.1%** |
| 과소평가 **하한** | 중앙값 **10.8년**, 최대 **22.0년** |

**하한은 이중으로 보수적이다** — 지정 요건이 「≥ 30년」이고 지정 시점도 오늘보다 앞서므로
실제 오차는 10.8년보다 크지 작지 않다. **모순이 13건 나왔다는 것 자체가 두 출처의 독립성을
증명한다**(소진공이 같은 대장으로 업력을 확인했다면 0건이 나왔어야 한다).

> **판정: 나이 축이 재는 것은 「영업 지속기간」이 아니라 「대장 등록 후 경과」다.**

대장 자신의 역사가 이걸 설명한다 — 영업중의 인허가 연도는 1963년 1건에서 1970s 517 →

**대장이 자기를 만든 역사**이고, 축이 아래쪽에서 **절단(censored)** 됐다는 뜻이다.
대장 이전부터 있던 가게는 **대장이 자기를 등록한 날**을 받는다.

### G-H — 축은 노포를 위쪽에 올리지만 맨 위에는 못 올린다 (2026-08-28, 측정 완료)

G-A가 오차의 크기를 쟀다면, 이건 **그 오차가 화면에서 무엇을 하는가**를 쟀다.
제3자가 업력을 인증한 노포 33곳이 지도의 어디에 그려지는지를 전수 대조했다.
합격선은 측정 전에 고정했다([`PREREG.md`](PREREG.md) 해시).

| | 값 | 합격선 | |
|---|---|---|---|
| 인증 노포의 대장 나이 **백분위 중앙값** | **94.8** | ≥ 92.0 | ✅ |
| **상위 100곳** 중 인증 노포 | **1곳** | ≥ 5 | ❌ |

- **위쪽에는 있다.** 인증 노포는 지도의 상위 6% 안에 제대로 들어간다. 축의 방향은 맞다.
- **맨 위에는 없다.** 상위 100곳의 나이 하한이 **54.0년**인데, 실제 창업 1904년경인
  **이문설농탕이 49.3년으로 그려져 탈락한다.** 「가장 오래된 집」을 찾는 사용자는
  121년짜리를 못 만난다.
- **나이 순 1위는 「골목식당」 115년(강남구)이고, 그것은 입력 오류다**
  (1911년 청담동은 성립하지 않는다 — 당시 경기도 광주군). 2위는 63년으로 **52년 벌어져 있다.**
- ⚠️ **색으로는 그 1위가 안 보인다.** 램프가 `min(경과,50)`으로 **50년에서 포화**하므로
  **50년 이상 265곳(0.24%)이 전부 같은 색**이다. 즉 화면은 115년짜리 오류와 54년짜리를
  구분하지 않고, **이문설농탕(49.3년)은 그 밴드 바로 아래**에 있다. 팝업의 값에서만 갈린다.
- 상위 20곳은 59~63년(1963~1967 등록)에 몰려 있고, 이 구간은 **대장 자신이 시작된 시기**다.
  상단은 「가장 오래된 가게」가 아니라 **「대장이 가장 먼저 등록한 가게」** 명단에 가깝다.

**한계**: 인증 노포 집합은 꼬리에 치우친 표본이다. 이 측정이 답하는 것은
**「노포가 화면 어디에 그려지는가」** 하나이고, 지도 전체의 정확도가 아니다.

    ([서울시 보도자료](https://news.seoul.go.kr/gov/archives/561960)).
    합계 일치를 전수의 증거로 읽은 것이 오류였다 — 한 장소 한 시각의 관측이 우주의 크기를
    말해주지 않는다. 실제 분류 목록은 미해결 3번에서 실측한다.
- `실호출` `LIVE_PPLTN_STTS`에 인구 신호가 통째로 들어온다: `AREA_CONGEST_LVL`(4단계),
  `AREA_PPLTN_MIN/MAX`, 성별 비율, **연령 8구간**(`PPLTN_RATE_0`~`_70`),
  `RESNT_PPLTN_RATE`/`NON_RESNT_PPLTN_RATE`(상주/비상주), 그리고 `FCST_PPLTN` —
  **시간 단위 인구 예보**. 국적·외국인 필드는 응답 전체에 **없다.**
- `실호출` 응답 최상위 블록은 **17개**. 핫플 모드가 쓰는 건 `LIVE_CMRCL_STTS` 하나뿐이고,
  나머지 16개는 **같은 호출에 딸려온다** — 추가 쿼터 없이 이미 손에 있다(미해결 11번 — 손대지 않는다).
- `문서` 한 번에 1개 장소씩만 호출 가능. 인구 5분 / 상권 10분 갱신

### 호출 쿼터 — 10분 갱신은 개발계정으로 불가능

개발계정 1,000건/일, 운영계정 100,000건/일. 그런데 장소당 1콜이므로:

```
120곳 × 6회/시 × 24시간 = 17,280건/일   →  개발계정 한도의 17.3배
개발계정으로 가능한 전 장소 갱신 = 하루 8회 (약 3시간 간격)
```

**운영계정 승인 없이는 "실시간 핫플"이 성립하지 않는다.** 승인 전까지는 3시간 간격이거나,
장소를 추려야 한다.

## 조인 문제는 사라졌다 (소상공인 API 미사용)

두 소스에 공통 키가 없다는 제약이 오래 설계를 지배했다 — 상가업소번호와 인허가관리번호는
서로 무관해서, 합치려면 상호명+주소 매칭이 필요하고 그 정확도가 품질의 상한이 됐다.

**합치지 않기로 했다.** LOCALDATA 한 레코드에 좌표(`X`/`Y`, 5174로 읽음)·업태(`UPTAENM`)·
시간축(`APVPERMYMD`)·상호·주소가 **전부 들어 있다.** 소상공인 상가정보가 추가로 주는 것은
"이미 있는 것의 다른 판본"뿐이고, 대신 시간축이 없다.

따라 닫히는 것: 매칭 평가 설계, 매칭 정확도 상한, 두 소스의 기준시점 정합.
**단 조건부다** — 나중에 LOCALDATA 밖 필드를 요구하는 설계가 나오면 이 결정은 다시 열린다.

**카카오·네이버 SDK를 안 골랐다** — 상용 지도 SDK는 공공누리와 별개의 이용조건을 새로 붙여
방금 통과한 약관 킬 게이트를 다시 여는 선택이다. 같은 이유가 배경 타일에도 적용된다(13번).

```
web/index.html                    14.7 KB  정적, 외부 런타임 의존 = 배경 타일 하나
web/vendor/maplibre-gl.{js,css}  848   KB  4.7.1 vendoring, 3-Clause BSD 전문 동봉
web/data/points.json               8.11 MB 109,066행 (gzip 2.33 / brotli 1.62)
```

로컬에서 보려면: `cd web && python3 -m http.server 8765` 후 `open http://127.0.0.1:8765/`
게시는 **GitHub Pages**(gzip 2.33 MB) — 위 「재개 지점」의 게시 목록 4번.

**프레임워크가 강제되는 지점은 핫플 모드가 화면에 오를 때다** — 결제는 갱신되므로 정적으로
못 굽는다. 정적 HTML → 프레임워크는 화면 하나라 싸고 반대는 비싸므로, 지금 안 정하는 쪽이
옵션을 연다. 두 모드 화면 배치(토글/탭/동시표시)는 **여전히 미정**이고 14번이 거기 걸린다.
